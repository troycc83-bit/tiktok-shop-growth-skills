# 爆款拆解 + 仿写（Video Remix）

## 目的

把"看爆款"变成可复用的资产。**学结构，不抄内容**——只复用让视频转化的叙事骨架，文案和画面全部按卖家自己的产品重写。这是整套系统里最高频、最核心的能力。

## 调用前必读

1. 共享知识库：`~/.workbuddy/skills/tiktok-shop-growth/shared-kb/winning-templates.md`（已验证骨架）和 `user-language.md`（买家真实措辞）、`product.md`（自家产品卖点）。有内容就作为输入；没有就跳过。
2. 拆解框架：`references/decompress-framework.md`（拆解维度 + 8 类 Hook + 10 战术 + CTA 库）。
3. 耳机骨架库：`references/earbuds-skeletons.md`（美区耳机 5 大验证骨架）。
4. 脚本框架复用：已有的 `sales-script-generator` Skill 的 `references/frameworks.md` 提供成熟的 PAS/AIDA/4Ps/社证前置 PAS 模板与战术库，本 Skill 与之兼容，可直接引用其模板，不必重写。

## 工作流（按需触发，无固定频率）

### 第 1 步：拿到视频内容（三选一，按可用性）

- **A. 视觉模型直读**：若当前模型支持视频理解，直接读视频画面 + 音轨。先尝试这条。
- **B. 本地拆解脚本**：若模型不支持视频，运行 `scripts/decompress_video.py` 自动完成抽帧 + 音轨转写：
  ```bash
  python3 ~/.workbuddy/skills/tiktok-video-remix/scripts/decompress_video.py <视频路径> --out <输出目录>
  ```
  脚本产出：关键帧图片序列 + 带时间戳的口播文本。逐帧读图识别画面、节奏、CTA 动作，配合台词定位说服目的。
- **C. 用户提供**：若只有链接（TikTok 网页反爬，不保证能抓到视频本体），先说明并建议用户下载视频文件后喂入；或用户截图 + 复制文案，则直接用文字输入分析。

如实告知用户用了哪条路径，不夸大能力。

### 第 2 步：结构化拆解（套框架）

按 `references/decompress-framework.md` 的维度逐项拆解，输出拆解表：

| 时间轴 | 画面 | 口播/字幕 | Hook类型 | 说服目的 | 战术 |
|--------|------|----------|---------|---------|------|

拆解要点：
- Hook 三通道：口播第一句 / 第一个画面 / 第一条字幕分别是什么，是否服务于同一 hook 类型
- 前 3 秒有无模式中断
- 痛点是否被放大到有画面感
- 演示手法：before/after、极限测试、场景代入、对比
- 信任状与 CTA 类型（与漏斗阶段是否匹配）

### 第 3 步：提炼骨架

从拆解表里抽象出**可复用叙事骨架**，明确标注：
- 必须保留的结构（如"前 3 秒不提产品名""评论墙前置"）
- 可替换的槽位（产品、卖点、人群、场景）

### 第 4 步：仿写到自家产品

输入自家产品卖点（从 `product.md` 读，或现场问用户；未知项标「待核实」，禁止编造参数/价格/功效）。产出：

1. **3–5 个英文 hook 变体**（换 hook 类型 / 换痛点切入 / 换 CTA）
2. **逐段分镜脚本**：`| 时间轴 | 画面 | 英文口播 | 屏幕字幕 | 拍摄备注 |`
3. **Caption + hashtag 组合**
4. **达人 Brief**（一页英文，达人拿到即可拍）：产品一句话、3 个必讲卖点、必须出现的演示动作、禁讲内容、时长、CTA、参考骨架

写作规则：
- 卖点 features→benefits 化，用买家语言（`user-language.md` 里的原话优先）
- 英文口播按 ≈2.5 词/秒估算，确保时长吻合
- 电商合规：避免「治疗/根治/100%」等绝对化与医疗功效词

### 第 5 步：验证建议 + 回流

- 给出先发哪个 hook、看哪个指标的建议（3 秒完播率 / 商品点击率 / 转化率）
- 若用户后续反馈某骨架跑赢，提醒主控把骨架写回 `winning-templates.md`

## 红线

- 不编造产品功效、成分、价格、销量数据；没有就标「待核实」
- 学结构不抄文案：hook 和结构可复用，具体措辞必须原创
- 参考视频仅作结构分析，不照搬他人创意内容
