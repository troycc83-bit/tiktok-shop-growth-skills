# 周报复盘（Weekly Review）

## 目的

回答两个问题：**哪里没达标、为什么**；以及**跑赢的东西怎么沉淀下来**。它同时是整套系统的闭环节点——把验证过的结果回流成可复用资产。

## 调用前必读

- 共享知识库 `~/.workbuddy/skills/tiktok-shop-growth/shared-kb/weekly-log.md`（历史记录）、`winning-templates.md`（骨架库）。
- 若为阶段复盘，读 `tiktok-sales-plan` 产出的计划表（用户需提供或从对话上下文取）。
- 复盘框架：`references/review-framework.md`。

## 工作流（按需触发，无固定频率）

### 第 1 步：拿到数据

- 用户提供 Seller Center 导出数据（订单、GMV、视频表现、达人产出等），或贴关键数字。
- 若用户只说"复盘一下"但没给数据，向用户要：对比周期 + 关键指标实际值 + 对应的计划值。
- 数据不足就基于能拿到的部分分析，并标注缺失项，不编造数字。

### 第 2 步：对比与定位偏差

按 `references/review-framework.md` 逐层拆解漏斗：

```
曝光 → 播放 → 商品点击 → 下单 → 成交
达人：建联 → 采纳 → 出单
```

找出**偏差最大的那一层**（不是平均用力），作为复盘重点。

### 第 3 步：归因

对偏差最大的环节，判断原因类别：
- 内容问题（hook 弱、演示不清、节奏差）
- 选品/产品问题（卖点不成立、价格带不对）
- 达人问题（选错人、建联不足、佣金无吸引力）
- 流量/投放问题（预算、时段、投放设置）

每个归因要给出依据，区分"数据支持的事实"和"推测"。

### 第 4 步：资产回流（核心闭环）

若某条视频/脚本/骨架**跑赢了**（转化或关键指标明显好）：
- 按 `winning-templates.md` 的格式，把它的**叙事骨架**（不是具体文案）追加写入共享知识库。
- 记录：骨架类型、验证结果、适用卖点、Hook 类型、时间轴骨架、为什么跑赢。
- 这样下次 `tiktok-video-remix` 仿写时会优先读它，形成复利。

### 第 5 步：输出 + 记录

输出一页纸复盘：
```
# 复盘：[日期/周期]
计划 vs 实际（关键指标表）
偏差最大环节 + 归因
下周 3 件事（可控动作）
资产回流：（本次沉淀了什么骨架 / 无）
```

同时把这条复盘追加写入 `weekly-log.md`（不覆盖历史）。

## 红线

- 不编造数据；用户没给的指标标「未提供」
- 归因要区分事实与推测，推测要说明依据
- 回流骨架只记结构，不照搬文案
- 行动项放可控动作，不放不可控结果
